01

COLABORACIÓN Y SEGUIMIENTO

Control de versiones

Administra el historial de un proyecto y trabaja en equipo sin perder cambios.

¿Qué es?

Es un sistema que registra los cambios realizados en archivos a lo largo del tiempo. Permite consultar versiones anteriores, comparar modificaciones, recuperar contenido y coordinar el trabajo de varias personas.

¿Cómo funciona?

  1. Se crea un repositorio para guardar el proyecto.
  2. Se modifican archivos y se revisan los cambios.
  3. Se prepara una selección de cambios (stage).
  4. Se registra una instantánea con un commit y un mensaje.
  5. Se comparten los cambios con el equipo y se integran cuando corresponde.

Tipos de sistemas

Local

Guarda versiones en el mismo equipo. Es sencillo y funciona sin red, pero colaborar y compartir el historial resulta difícil.

Ejemplo: copias versionadas locales
Centralizado (CVCS)

Un servidor conserva el repositorio principal y los usuarios obtienen una copia de trabajo. Facilita la administración central, pero depende del servidor y de la conexión para muchas operaciones.

Ejemplo: Subversion (SVN)
Distribuido (DVCS)

Cada integrante tiene una copia completa del repositorio y su historial. Permite trabajar sin conexión y ofrece flexibilidad; requiere aprender a sincronizar e integrar ramas.

Ejemplo: Git

Características, ventajas y desventajas

TipoCaracterísticasVentajasDesventajas
LocalHistorial en un solo dispositivo.Simple, rápido y sin servidor.Riesgo de pérdida del equipo; colaboración limitada.
CentralizadoServidor central y copias de trabajo.Control administrativo y punto único de referencia.Dependencia del servidor y posible cuello de botella.
DistribuidoCopias completas e historial local.Trabajo sin conexión, ramas ágiles y redundancia.Puede requerir más espacio y coordinación al fusionar cambios.

Las ventajas y desventajas son generales; pueden variar según la herramienta y la forma de trabajo.

Rastreo y gestión de cambios

El historial permite saber qué cambió, quién lo modificó, cuándo y, mediante mensajes o revisiones, por qué. Las ramas aíslan funciones; las comparaciones muestran diferencias; las fusiones incorporan trabajo y los conflictos se resuelven revisando las líneas modificadas.

Comandos básicos de Git 
git init
git status
git add .
git commit -m "Describe el cambio"
git branch nueva-funcion
git push

Ejemplo: en una app escolar, una persona crea una rama para agregar recordatorios. Otra corrige el calendario. Después revisan e integran ambas mejoras en la rama principal.

02

ALMACENAMIENTO Y CONSULTA

Persistencia y acceso a datos

Conserva información aunque la aplicación se cierre o el dispositivo se reinicie.

Definición y características

La persistencia de datos es la capacidad de guardar información para recuperarla posteriormente. Un mecanismo adecuado considera estructura, disponibilidad, rendimiento, seguridad, capacidad, sincronización y ciclo de vida de los datos.

▤

Archivos

Guardan información como texto, JSON, imágenes, audio o documentos. Son útiles para contenido completo o documentos que no necesitan consultas relacionales complejas.

Ejemplo: preferencias exportadas o una imagen descargada.

Ventaja: formato flexible. Desventaja: buscar, actualizar y relacionar datos puede requerir lógica adicional.

▦

Base de datos local

Almacena datos estructurados en el dispositivo. SQLite es un motor relacional; Room es una biblioteca de persistencia que facilita trabajar con SQLite en Android.

Ejemplo: tareas, fechas de entrega y materias sin conexión.

Ventaja: consultas y relaciones eficientes. Desventaja: sincronizar varios dispositivos requiere una estrategia adicional.

☁

Base de datos remota y servicios web

Los datos viven en un servidor o servicio en la nube y se consultan mediante una API, comúnmente HTTP/HTTPS. Facilita compartir y sincronizar información.

Ejemplo: iniciar sesión y consultar tareas desde distintos teléfonos.

Ventaja: acceso compartido. Desventaja: depende de red/servidor y exige proteger la comunicación.

¿Qué datos se pueden almacenar?

FormaDatos adecuadosEjemplos de uso
ArchivosTexto, JSON, PDF, imágenes, audio y video.Documentos, exportaciones, fotografías y caché.
Base localRegistros estructurados: números, texto, fechas, estados y relaciones.Contactos propios de la app, inventario o tareas.
RemotaDatos compartidos, cuentas, catálogos y registros sincronizados.Perfiles, compras, contenido y respaldo centralizado.

Mecanismos de acceso

  • Bibliotecas de clases: reúnen funciones para leer y escribir datos. Ejemplos: APIs de archivos, preferencias y bibliotecas de red.
  • Clases de SQLite: permiten crear tablas, insertar, consultar, actualizar y eliminar registros mediante SQL. En Android se recomienda considerar Room para reducir código repetitivo y validar consultas.
  • Mapeo relacional de objetos (ORM): relaciona tablas con clases y filas con objetos. Facilita trabajar desde el lenguaje de programación; no elimina la necesidad de diseñar bien la base de datos.

Autenticación y consumo de servicios web

  1. La app solicita credenciales o usa un proveedor de identidad.
  2. El servidor valida la identidad y emite un token de acceso.
  3. La app envía solicitudes HTTPS a la API, adjuntando el token cuando corresponde.
  4. El servidor verifica permisos y devuelve datos, normalmente en JSON.
  5. La app valida la respuesta, actualiza la interfaz y maneja errores o expiración del token.

Nunca guardes contraseñas en texto plano ni incluyas secretos privados dentro del código de la aplicación.

Ejemplo práctico: una aplicación de tareas guarda las tareas recientes en Room para consultarlas sin internet y sincroniza los cambios con una API cuando vuelve la conexión.

INTERACCIÓN CON EL ENTORNO

Gestión de sensores

Obtén información del movimiento, orientación y condiciones del entorno.

¿Qué son los sensores?

Son componentes físicos o virtuales que detectan cambios del entorno o del propio dispositivo y generan datos que una aplicación puede interpretar.

↔
Acelerómetro

Mide aceleración en los ejes; detecta movimiento, inclinación aproximada y sacudidas.

⟳
Giroscopio

Mide velocidad angular; ayuda a reconocer giros y rotaciones.

⌖
Magnetómetro

Mide el campo magnético y ayuda a estimar la orientación tipo brújula.

☼
Luz ambiental

Mide la iluminación alrededor del dispositivo.

⇧
Proximidad

Detecta objetos cercanos, por ejemplo al acercar el teléfono al rostro.

⌁
GPS / ubicación

Obtiene posición estimada mediante proveedores de ubicación; no es un sensor físico único.

Proceso de gestión

1Habilitación

Verificar que el sensor exista, solicitar permisos cuando aplique y explicar al usuario el uso de datos.

2Obtención

Registrar un listener o suscribirse a actualizaciones con la frecuencia necesaria.

3Procesamiento

Filtrar ruido, combinar lecturas, interpretar unidades y reaccionar a eventos.

4Liberación

Detener las lecturas cuando ya no se necesitan para ahorrar batería y proteger la privacidad.

Ejemplo: una app de actividad física obtiene aceleración durante el ejercicio, filtra variaciones y estima pasos. La precisión depende del dispositivo y del algoritmo.

04

EXPERIENCIA DE USUARIO

Uso de recursos multimedia

Integra elementos visuales y sonoros para comunicar y enriquecer la interacción.

▧

Imágenes

Fotografías, iconos, ilustraciones y gráficos. Se utilizan en perfiles, galerías y botones. Conviene optimizar tamaño y resolución.

♫

Audio

Música, efectos y voz. Se reproduce, graba o procesa con componentes de audio, respetando permisos y controles del usuario.

▶

Video

Clips grabados o transmitidos. Requieren decodificación, controles de reproducción y adaptación a la conexión.

✧

Animaciones

Transiciones y movimiento entre estados. Orientan al usuario y ofrecen retroalimentación sin distraer.

◌

Elementos dinámicos

Gráficas, mapas, visualizaciones y componentes que cambian según datos o acciones del usuario.

▣

Accesibilidad

Usa texto alternativo, subtítulos, controles claros y evita depender únicamente del color o del sonido.

¿Dónde se almacenan?

  • Recursos empaquetados: dentro de carpetas de recursos del proyecto, por ejemplo res/drawable, res/mipmap o res/raw en Android.
  • Assets: archivos originales que se leen desde la carpeta assets.
  • Almacenamiento del dispositivo: contenido creado o descargado por el usuario.
  • Servidor o nube: multimedia compartida o entregada bajo demanda.

Componentes de software

  • Visores de imágenes y bibliotecas de carga.
  • Reproductores y grabadores de audio/video.
  • Cámaras y selectores de archivos del sistema.
  • APIs de animación, gráficos y renderizado.
  • Decodificadores, caché y gestores de descargas.

En Android se encuentran APIs como CameraX, Media3/ExoPlayer y APIs gráficas, según la necesidad.

05

PROCESOS Y CONECTIVIDAD

Servicios y notificaciones

Ejecuta tareas oportunas y comunica información relevante al usuario.

Conceptos básicos

Un servicio es un componente que realiza operaciones sin necesitar una pantalla propia. Las tareas en segundo plano son trabajos que continúan cuando la app no está visible, sujetos a límites de batería y del sistema operativo. Una notificación es un mensaje que aparece fuera de la interfaz principal para informar o solicitar una acción.

Tareas en segundo plano

Se usan para sincronizar datos, subir archivos, procesar contenido o actualizar información. Deben programarse con criterios de prioridad, conectividad, batería y duración.

Android: WorkManager es apropiado para trabajo diferible y persistente. Para tareas inmediatas o visibles existen mecanismos específicos, sujetos a restricciones de versión.

Tratamiento de notificaciones

  1. Definir el evento que justifica avisar.
  2. Solicitar permiso de notificaciones cuando la versión del sistema lo requiera.
  3. Crear el canal de notificación en Android.
  4. Preparar título, texto, icono y acción.
  5. Publicar y permitir que el usuario gestione preferencias.

Proceso de implementación

01Proveedor de contenido

Define datos que pueden compartirse entre aplicaciones mediante una interfaz controlada, con permisos y operaciones de consulta o modificación.

02Tarea de fondo

Define el trabajo, sus restricciones y cuándo debe ejecutarse; gestiona reintentos y resultados.

03Notificación

Construye el aviso, configura canal y permiso, lo publica y atiende las acciones del usuario.

Servicios de cómputo en la nube

Permiten utilizar infraestructura, almacenamiento, bases de datos, autenticación, análisis y notificaciones mediante internet. Ejemplos de plataformas: Firebase, Amazon Web Services (AWS), Microsoft Azure y Google Cloud.

La nube facilita escalar y sincronizar, pero implica costos, dependencia de conectividad, configuración de seguridad y cumplimiento de privacidad.

CALIDAD Y MANTENIMIENTO

Librerías, toolkits, depuración y seguridad

Aprovecha componentes existentes, detecta errores y protege la aplicación.

¿Qué es una librería?

Es un conjunto reutilizable de código que ofrece funciones o componentes para resolver tareas concretas. La aplicación llama a la librería cuando necesita una operación.

Ejemplos: Retrofit o Ktor Client para comunicación HTTP; Room para persistencia; Glide o Coil para carga de imágenes.

¿Qué es un toolkit?

Es un conjunto integrado de herramientas, bibliotecas y utilidades para construir una aplicación o una parte de ella. Puede incluir componentes visuales, compilación, pruebas y documentación.

Ejemplos: Android SDK, Jetpack Compose y Flutter SDK.

Diferencias entre toolkits móviles

Toolkit / plataformaEnfoqueCaracterísticasConsideración
Android SDKDesarrollo nativo Android.APIs oficiales, emulador y herramientas de plataforma.Principalmente orientado a Android; Kotlin y Java son opciones habituales.
Jetpack ComposeInterfaz nativa Android.UI declarativa con Kotlin y componentes modernos.Se integra en proyectos Android; no es un toolkit multiplataforma por sí solo.
FlutterMultiplataforma.UI basada en widgets y lenguaje Dart.Permite compartir gran parte de la interfaz y lógica, aunque puede requerir integración nativa.
React NativeMultiplataforma.Desarrollo de interfaces con JavaScript/TypeScript y React.La integración y el rendimiento dependen de módulos y arquitectura usados.

Depuración

Es el proceso de localizar, analizar y corregir errores de un programa. Se utilizan puntos de interrupción, ejecución paso a paso, inspección de variables, registros y pruebas.

  • Android Studio Debugger: permite pausar la ejecución e inspeccionar variables.
  • Logcat: muestra mensajes y errores del sistema y de la app.
  • Profiler: ayuda a analizar uso de CPU, memoria y energía.
  • Emulador y pruebas: reproducen escenarios y dispositivos.

Seguridad

Consiste en proteger datos, identidad, comunicaciones y funcionamiento de la aplicación frente a accesos o acciones no autorizadas.

  • Solicitar solo permisos necesarios y explicar su uso.
  • Usar HTTPS y validar certificados.
  • Proteger credenciales y tokens; evitar secretos en el código.
  • Validar entradas y controlar accesos por roles.
  • Mantener dependencias actualizadas y revisar vulnerabilidades.
  • Probar, analizar y revisar el código antes de publicar.
Ejemplo: si una pantalla se cierra inesperadamente, el desarrollador revisa Logcat, reproduce el error, coloca un breakpoint, inspecciona variables, corrige la causa y ejecuta pruebas de regresión.
